# A股雷达｜日报归档中心

## 产品方向（优先级最高）

这个项目以**每天18:00 ChatGPT 推送的《A股启动与卖出雷达》报告归档与阅读**为主，不再把行情统计仪表盘当作产品首页。

- 首页：https://dicky-l.github.io/a-share-radar/ —— 日报列表、全文阅读、按日期/月份/股票/关键词搜索、永久链接。
- 原行情工作台：https://dicky-l.github.io/a-share-radar/market.html —— 只用于辅助核对市场快照。
- 报告正文：`reports/YYYY-MM-DD.md`。每期一个文件，便于 Git 版本追踪。
- 检索索引：`scripts/build_report_index.py` 在 Pages 发布时自动从真实报告生成 `reports/index.json`。
- 历史补录：2026-10-15 至 2026-10-19 首次导入的是**精简历史摘要**，不是逐字的原始日报；页面标记摘要，不伪造全文。
- 真实归档：从新一期开始应保存当天已实际产生的推送原文，经隐私处理后写入 `reports/YYYY-MM-DD.md`，`status: original`。不要编造不存在的报告。

## 新增一篇完整日报的流程

1. 在 ChatGPT 18:00 定时任务完成后获取**该次任务真实输出正文**，不要根据股价重新生成一份事后报告。
2. 转成可读的 Markdown 归档文本（包括必要的真实来源 URL，不使用仅 ChatGPT 可解析的内部引用和沙盒图片路径）。
3. 不将真实持仓成本、数量、账户信息、联系方式等个人敏感信息上传**公开 GitHub**。如含隐私信息，先脱敏/改为只含公共内容的归档副本；完整私人版必须使用私有存储。
4. 生成 `reports/YYYY-MM-DD.md`，文件首部示例：

```text
---
date: 2026-10-21
title: A股启动与卖出雷达｜2026-10-21
status: original
source: ChatGPT 18:00 日报公开脱敏版
preview: 一句话说明当天关键风险与观察方向
---

# A股启动与卖出雷达｜2026-10-21

（粘贴当天真实推送正文）
```

5. 使用已经授权的 GitHub connector 将文件写到仓库 `Dicky-L/a-share-radar` 的 `main` 分支（当日重复写入需要获取现有 blob SHA 更新）。
6. `.github/workflows/pages.yml` 因 `reports/**` 文件变化自动执行：生成检索目录并重新部署 GitHub Pages。
7. 进入网站核对文章日期、全文、链接；失败时保留日志，**不能宣称已自动归档**。

## 关于“每天自动从 ChatGPT 推送同步到网页”

**注意：ChatGPT 的 18:00 任务输出与 GitHub Pages 之间目前没有已经验证的自动传输通道。**

本仓库已经实现 **GitHub 收到日报文件 → 索引更新 → Pages 发布** 的自动化后半程；而 **ChatGPT 定时任务产出 → GitHub 仓库写入** 的前半程，必须由具有 GitHub 写入权限的任务/连接器真正执行并核验，或者手动让助手同步。单纯在 GitHub Actions 设置 cron 无法读取用户的 ChatGPT 私有推送。

原定时任务保持北京时间18:00不变。行情快照采集（18:15）是另一个独立工作流。

## 数据保留与版本

日报是**发布时快照**：保留原当日推送结论和失败样本。修订时应明确记录修订原因与时间，不能借用后来行情数据去重写当时观点。

## 阅读与金融术语呈现规范

- **保留专业术语与原始论证**：历史原文、推送任务以及可核实的行情数字不因阅读模式而改写。
- **正文为主、解释按需**：不把整篇报告重新翻译成口语。只有读者点按术语时，展示标准定义、适用范围、计算公式（可用时）和投资分析要点。
- **可用性改造不是简化研究**：允许章节跳转、折叠、字级缩放和阅读配色切换；不删除金额、数据源、模型条件、失败样本、结构失效位等专业信息。
- **历史摘要明确标记**：已补录的10月15—19日摘要仍不是原始全文，不能改名为“完整研究”。后续只在获取原始推送正文时才归档为 `status: original`。
- **不强制改写原定时推送**：所有变化只应用在网站阅读层，18:00任务照常按原专业报告规则运行。
