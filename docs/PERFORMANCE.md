# 选股绩效总览：定义、数据边界和验收标准

本项目以**选股、买入验证、卖出管理、结果复盘**为中心。市场数据图表只是辅助证据。

## 已实现（2026-10-21）

- `performance.html` 为独立、可筛选的推荐历史总览页面，按当期股票与日期展示后续收盘走势；与首页的逐股推荐卡片互相链接。
- `reports/recovered-details.json` 保存从此前可检索的历史推送记录中恢复的部分逐股观察位、失效位和止盈参考。**这是追溯补充，不是原始18:00推送全文**；日期保持当时归属，不能作为当前买卖条件。
- `scripts/build_candidate_index.py` 基于实际报告表格及明确存在的文字候选归档，再补充有来源的历史条件；如缺少字段，保留空值，不编造。
- `scripts/build_performance.py` 利用数据仓库已经验收的每个交易日收盘价，计算D+1/D+3/D+5/D+10的盘后价差百分比。网页展示逐日走势、已核验记录及待观察样本。
- GitHub Pages部署时自动构建 `reports/candidates.json` 和 `reports/performance.json`，失败则发布失败，不展示伪造的绩效结果。

## 计算方式（不是交易收益）

- 报告发布在18:00，**基准**取该报告日期当天或之前最近一个交易日的已归档收盘价，绝不表示此价可用于报告发布后的买入。
- D+1指报告后的第一个有效交易日（非自然日；周末报告的基准为前一交易日收盘价）。
- **D+N收盘变化率** = （报告后第N个交易日收盘价 / 观察基准收盘价 - 1）×100%。
- 未到D+N，或对应股票缺行情，结果标记**待观察**，不得补成0。
- 同一只股票重复推荐按日期分别保留，同时统计股票代码去重数；这些记录相关，不应当当作独立样本计算策略胜率。
- 原来记录在C池或“历史复盘”的股票，不偷换成当日新推荐。
- 观察期最高/最低**收盘变化**不能误称盘中最大盈利/最大不利波动；当前没有足够的日内OHLC和成交执行数据来确定入场真实触发。

## 真实赚钱需要的第二套验证

盘后观察结果仅检验选股方向，还不能证明可以赚钱。可执行交易结果至少需要：

1. 冻结每次推荐当天的观察价格、技术/基本面理由、买入确认、无追高位、结构失效、止盈和时间退出条件。
2. 接入历史OHLC、涨跌停/停牌状态、交易量、除权分红、指数基准；对盘中价位触发须验证时序，不能用收盘后才知道的行情假设早盘已买入。
3. 计算“是否触发入场 → 实际可能成交价 → T+1 → 止损/止盈/分批成交 → 手续费和滑点 → 实际可执行盈亏”，允许**根本未买入**的结果。
4. 冻结一段样本作为样本外验证，按不同市场环境统计收益分布、最大回撤、盈亏比、执行率；胜率只是其中一项。
5. 真实持仓成本与仓位涉及个人财务隐私，只能放在本地或用户明确授权的私有存储，不能上传到公开GitHub仓库。

## 初始证据与限制

- 当前历史行情归档覆盖2026-09-21至2026-10-20共16个交易日；完整选股日报只回填了2026-10-15至19日五篇摘要。
- 当前可提取13条“当期观察候选”记录、涉及6个股票代码；其中D+1可核验13条、D+3仅2条。**样本非常少且重复，不足以证明策略盈利能力。**
- 2026-10-19三只B池的10月20日收盘价均较10月19日下跌：中国核电9.57→9.53、中国广核4.61→4.56、生益科技117.63→117.23。
- 此前历史推送观察位部分从可检索消息恢复，不能把已恢复的细节误称为已获得原始完整推送全文。严格保留 `report_status: summary`。
- 价格来自不复权历史回填和腾讯行情的不同口径，跨分红除息日不能将收盘价变化简单当成真实总回报。
- 这个工具不能保证收益；频繁交易、追高和单一股票高集中度有可能损失本金。

**当前第一阶段目标是识别真正有效的候选与无效信号，而不是追求漂亮的“上涨概率”或虚构回测胜率。**
