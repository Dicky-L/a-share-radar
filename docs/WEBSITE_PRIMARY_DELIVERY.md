# A股启动与卖出雷达：网站为每日完整报告首发阅读入口

## 正确产品目标（2026-10-22）

**不是旧文归档网站，也不是市场行情仪表盘。** 用户每天打开 https://dicky-l.github.io/a-share-radar/ ，优先阅读北京时间18:00形成的**当期完整选股研究报告**：

1. 今日选股决策结论（A/B/C池，可无A池）
2. 逐股逻辑、真实收盘价、入场确认、不追高约束、结构失效、分批退出与利润保护
3. 市场总览、同口径双日行业资金图、成交额与风险
4. 上期推荐兑现、历史冻结批次的成功与失败
5. 信息源、日期和局限、全文原文

网页保留专业术语，可按需查定义，并通过图表辅助理解。原始报告正文比摘录卡片具有更高证据优先级。**市场行情快照绝对不能冒充当日ChatGPT推送的完整选股研报。**

## 网站交互合同

- 裸主页 `/`：每次访问按北京时间计算“今天”，优先展示当天已归档报告；若未发布则明确写 `今天的选股报告尚未同步`，并显示最近一期**真实**报告而不是市场行情。
- 直达链接 `/?date=YYYY-MM-DD`：打开指定日期已归档报告；如果该日期只有行情，没有报告，标 `仅行情`；不得伪造当期推荐。
- 裸首页URL不会自动被写入历史日期参数，避免第二天仍被锁定到昨天。
- `reports/YYYY-MM-DD.md` 一期一个完整文章，首部字段 `date`, `title`, `status`, `source`, `preview`；**仅当天真实生成的完整正文可设 `status: original`**。回填的摘要使用 `status: summary`。
- GitHub Pages发布时由 `scripts/build_report_index.py` 重新生成 `reports/index.json` 和其他辅助图表、选股索引；浏览器每次请求索引时避免缓存。
- 站内仍提供月度历史、选股绩效、行情查询，但这些是日报的辅助页面。

## 自动化交付合同：18:00 → GitHub → 网站

- ChatGPT原有北京时间18:00任务保持启用，完整研究仍要生成。此次已加强发布要求：同一次执行中**尝试**把该次公开脱敏后的完整Markdown文章写入 `Dicky-L/a-share-radar` 的 `main/reports/YYYY-MM-DD.md`，并核对源文件存在。
- GitHub写入触发 `.github/workflows/pages.yml`，自动重建索引并部署站点。**只有仓库写入、页面部署和真实浏览可读均核验后，才能报告网站同步成功**。
- 若任务环境中不支持GitHub连接器、内容写入失败或公开脱敏不安全，任务仍在ChatGPT发送完整报告，必须提示网站发布失败，不能只发一个空白链接。
- `.github/workflows/verify-report.yml` 北京时间18:45检查当天是否存在足够完整的 `status: original` 报告；失败会在Actions任务中显式显示。它**无法凭空读取ChatGPT私有任务内容，也不会创建伪造报告**。
- 截至2026-10-22本次检查，已有定时任务执行记录，但GitHub仓库中尚无 `reports/2026-10-22.md` 的全文。当前仍**不能声称每天自动发到网站已验证成功**。明天及未来的18:00任务需通过真实执行验证连接器访问和实际部署。

## 安全与收益边界

- 此为公开Pages网站，**禁止提交账户编号、实际持仓数量、成本、私人财务资产及可识别个人信息**。只能公开安全脱敏副本；如无法安全脱敏，应保留私人原报告、网站显示同步失败。
- 所有A/B/C池和买卖条件属于研究观察，非保证收益；真实策略需入场触发、T+1、涨跌停、成本、滑点及历史失败记录的复盘。
